# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An Arduino sketch (`TrainDisplay/`) that ports Chris Crocker-White's Raspberry Pi [Train Departure Display](https://github.com/chrisys/train-departure-display) to an ESP32-S3 driving an SSD1322 256x64 OLED. The goal is fidelity to the original: screens, layout, text and scrolling are reproduced from its `src/main.py` and `src/trains.py`, and comments refer back to those files. When you change rendering or text building, keep it pixel- and text-identical to the original unless the change is deliberate (deliberate differences are listed under "Changes from the original" in the README).

## Build

There are no tests and no linter. CI only checks that the sketch compiles.

`TrainDisplay/secrets.h` is git-ignored and required to compile. Copy it from `secrets.example.h` (CI writes a blank one so release firmware starts the setup hotspot).

```sh
arduino-cli compile --fqbn esp32:esp32:esp32s3:PartitionScheme=min_spiffs,PSRAM=enabled,USBMode=hwcdc,CDCOnBoot=cdc TrainDisplay
```

Add `--upload -p /dev/cu.usbmodemXXXX` to flash over USB, or `-p train-display.local --protocol network --upload-field password=...` for OTA. Serial runs at 115200 baud. CI pins the ESP32 core to `esp32:esp32@3.3.12`, with `U8g2@2.36.19` and `ArduinoJson@7.4.3`. The `min_spiffs` partition scheme is needed for the two OTA slots.

## Architecture

- **Two cores.** `loop()` in `TrainDisplay.ino` runs the display (about 63 fps), the web server and ArduinoOTA via `serviceNetwork()`. `fetchTask` is pinned to core 0 and does the HTTPS fetches, so scrolling never stalls.
- **Double-buffered boards** (`app.h`). `boards[2]` live in PSRAM. The fetch task fills `boards[1 - frontBoard]`, then swaps `frontBoard` and sets `dataState` under `boardLock`. The display only reads the front board. `requestRefresh()` wakes the fetch task with a task notification.
- **Settings** (`settings.*`). These are stored per key in the `Preferences` namespace `tdd`. `config.h` and `secrets.h` hold only the first-boot and reset defaults. `getSettings()` returns a copy taken under a mutex. `applySettings()` validates the settings, saves them and bumps `settingsVersion`, which the display loop and fetch task poll to pick up changes. To add a setting, touch the struct, `defaults()`, `loadSettings()`, `validate()`, `applySettings()`, the JSON handlers in `net.cpp`, and the form in `web_ui.h`.
- **Data** (`rail.*`). This calls the Rail Data Marketplace Live Departure Board JSON API (v1.2, `x-apikey` header, pinned root CA in `root_ca.h`). It makes one request per destination CRS filter, then merges and sorts the results with after-midnight ordering. It builds the "Calling at" text exactly as `trains.py` does.
- **Network** (`net.*`). This handles Wi-Fi, the fallback setup hotspot with captive portal, the web UI and JSON API (`/api/*`, Basic auth as `admin` with lockout), firmware upload, ArduinoOTA and mDNS (`train-display.local`). It also handles OTA rollback: new firmware is marked valid after a minute on the network, or rolled back after 10 minutes or a crash.
- **Web page.** The whole settings page is one PROGMEM string in `web_ui.h`.
- **Fonts.** `dmfont.*` is a small 1-bit renderer whose metrics mirror Pillow's `getlength` and `getbbox`. `dotmatrix_fonts.h` is generated by `tools/fontconv.py`, so don't hand-edit it. Regenerate it with the commands in the README, which use a venv in `tools/.venv`.
- **Second display.** It shares the SPI, DC and RST lines with the first and has its own CS on GPIO 7. Each frame is drawn once per screen, each with its own platform filter.

## Releases

`FW_VERSION` in `TrainDisplay/app.h` must match the pushed `v*` tag, or CI fails. The release notes are taken from the `## <version> ` section of `CHANGELOG.md`, so bump both together. CI publishes `train-display-<v>-full.bin` (the merged image, flashed at 0x0) and `-update.bin` (for OTA).
